# KajiShare

KajiShare は、家族・同居人・チームで家事や日常タスクを分担し、進捗・評価・通知を共有するためのタスク管理アプリです。

「誰が何を担当しているか」「どのタスクが完了しているか」「完了した作業がどう評価されたか」をひとつのサービス上で確認できるようにし、家事分担の偏りや確認漏れを減らします。

## 主な特徴

### ログイン機能

KajiShare は OAuth 認証を利用した Google アカウントでのログインに対応しています。
ログイン後はユーザー情報に紐づいてグループ、タスク、通知、評価などを管理できるため、複数端末からでも同じアカウントで利用できます。

Google ログインでは、ユーザーが Google の認証画面で本人確認を行い、認証に成功するとアプリ側でログイン状態を作成します。
アプリ内では Google から取得したユーザー情報をもとに利用者を識別し、初回ログイン時はユーザー情報を作成します。

2回目以降のログインでは、同じ Google アカウントに紐づくユーザーとして扱われます。
これにより、ユーザーは新しくパスワードを作成・管理する必要がなく、Google アカウントを使って安全にログインできます。

### ゲストログイン機能

Google アカウントを使わずに、ゲストユーザーとしてアプリを試すこともできます。
ゲストログインを使うことで、アカウント登録前でもタスク管理やグループ機能の操作感を確認できます。

ゲスト利用中に認証情報が期限切れになった場合は、専用の案内ページへ遷移します。
通常ユーザーとゲストユーザーのどちらでも、安心して画面を利用できます。

### グループ単位のタスク管理

家族、ルームメイト、チームなどの単位でグループを作成し、メンバーを招待できます。
タスク、担当者、評価、通知はグループごとに整理されるため、複数の生活単位を分けて管理できます。

グループには管理者とメンバーの役割があります。管理者はグループ設定や周期タスクの管理を行い、メンバーは割り当てられたタスクの確認・更新を行えます。

### タスクの作成と割り当て

グループ内でタスクを作成し、メンバーへ割り当てられます。
タスクには名前、説明、負担ポイントを設定できるため、作業内容だけでなく「どれくらい大変なタスクか」も共有できます。

割り当てられたタスクは「担当のタスク」画面で確認でき、ステータスを着手前・進行中・完了へ更新できます。

### 周期タスクの管理

毎週発生する家事や定期的な作業は、周期タスクとして管理できます。
「ゴミ出し」「風呂掃除」「買い出し」など、繰り返し発生する作業を事前に登録しておくことで、毎回タスクを作成する手間を減らせます。

周期タスクには開始日、曜日、負担ポイント、説明を設定できます。

### 自分の担当タスクをすぐ確認

ダッシュボードや担当タスク画面では、自分に割り当てられているタスクを確認できます。
タスクの進捗や最近割り当てられたタスクが見えるため、今やるべき作業を把握しやすくなっています。

### 完了タスクの評価

他のメンバーが完了したタスクに対して評価を登録できます。
単にタスクを終わらせるだけでなく、作業の貢献度や取り組みをグループ内で見える化できます。

評価済みのタスクは重複して評価されないように扱われ、評価対象から自分自身の担当タスクは除外されます。

### 通知機能

タスクの割り当てや評価など、重要なイベントは通知として確認できます。
ヘッダーの通知アイコンには新着通知がある場合に印が表示され、通知一覧画面で詳細を確認できます。

通知の既読状態はユーザーごとに管理されるため、同じ通知で何度も新着表示されません。

### ダークモード

ヘッダーからライトモードとダークモードを切り替えられます。
表示設定はブラウザに保存され、次回アクセス時も選択したテーマが維持されます。

## 主な画面

- ダッシュボード: 自分の担当タスク、最近の割り当て、評価されたタスク、参加グループを確認
- タスク一覧: グループごとの通常タスク・周期タスクを確認
- 担当のタスク: 自分に割り当てられたタスクのステータスを更新
- 評価: 他メンバーが完了したタスクを評価
- 通知: タスク割り当てや評価などの通知を確認
- グループ設定: グループ情報、管理者、参加メンバー、招待情報を確認
- 周期タスク管理: 繰り返し発生するタスクを作成・編集・削除
- アカウント設定: アカウント情報や退会操作を管理
- ヘルプ: KajiShare の概要や問い合わせフォームを確認

## デプロイ構成

このリポジトリは KajiShare のフロントエンドアプリケーションです。
タスク、グループ、通知、評価、認証などのデータは KajiShare バックエンド API と連携して取得・更新します。

デプロイ先では、フロントエンドからバックエンド API にアクセスできる状態にしたうえで、認証・メール送信・公開URLに関する環境変数を設定してください。

## 環境変数

### 必須

```env
API_URL=https://api.example.com/api/v1
GOOGLE_CLIENT_ID=your-google-client-id
GOOGLE_CLIENT_SECRET=your-google-client-secret
AUTH_SECRET=your-auth-secret
AUTH_URL=https://app.example.com
```

- `API_URL`: KajiShare バックエンド API の URL
- `GOOGLE_CLIENT_ID`: Google OAuth クライアント ID
- `GOOGLE_CLIENT_SECRET`: Google OAuth クライアントシークレット
- `AUTH_SECRET`: NextAuth / Auth.js のセッション署名などに使う秘密値
- `AUTH_URL`: デプロイ後の KajiShare フロントエンド URL

`API_URL` は `/api/v1` 付きでも、ベース URL のみでも扱える箇所があります。
ただし、アプリ全体では `/api/v1` 配下の API を前提にしているため、デプロイ環境では `/api/v1` まで含めた URL を指定することを推奨します。

### 推奨

```env
APP_TIME_ZONE=Asia/Tokyo
FRONTEND_URL=https://app.example.com
```

- `APP_TIME_ZONE`: 担当タスクなどの日付計算で使うタイムゾーン
- `FRONTEND_URL`: バックエンド API へ送る Origin 判定用のフロントエンド URL

`FRONTEND_URL` が未設定の場合、`AUTH_URL`、`NEXTAUTH_URL`、`NEXT_PUBLIC_APP_URL`、Vercel の公開 URL などからフロントエンド URL を推定します。

### 問い合わせフォーム

問い合わせフォームからメールを送信する場合は、SMTP 設定も必要です。

```env
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=your-smtp-user
SMTP_PASS=your-smtp-password
SMTP_FROM=no-reply@example.com
CONTACT_TO=contact@example.com
```

### バックエンド連携用の共有シークレット

バックエンド側でフロントエンドからのサーバー間リクエストを検証する場合は、必要に応じて以下を設定します。

```env
FRONTEND_API_SECRET=your-shared-secret
```

## 認証設定

Google ログインを利用するため、Google Cloud Console で OAuth クライアントを作成し、デプロイ後の URL を許可済みリダイレクト URI に登録してください。

```text
https://app.example.com/api/auth/callback/google
```

`app.example.com` は実際に公開する KajiShare のドメインに置き換えてください。

## ビルドと起動

デプロイ環境では、以下のコマンドを利用します。

```bash
npm install
npm run build
npm run start
```

Vercel など Next.js 対応のホスティングサービスを使う場合は、通常は以下の設定でデプロイできます。

- Build Command: `npm run build`
- Output Directory: `.next`
- Install Command: `npm install`

## デプロイ前チェック

- `API_URL` が本番用バックエンド API を指している
- Google OAuth のリダイレクト URI が公開URLと一致している
- `AUTH_SECRET` が十分に安全なランダム文字列になっている
- `AUTH_URL` または `FRONTEND_URL` が公開URLを指している
- 問い合わせフォームを使う場合、SMTP 設定と `CONTACT_TO` が設定されている
- バックエンド側で CORS / Origin / 認証トークンの受け入れ設定が完了している

## 品質チェック

デプロイ前に以下を実行して、Lint と TypeScript の型チェックを確認します。

```bash
npm run lint
npx tsc --noEmit
```
